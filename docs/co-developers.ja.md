## 1. Zee の役割

Zee は、**侵入が成立した後に被害が拡大することを抑止する**ための実装です。侵入の防止を担う製品は既に多数存在します。Zee が担当するのはその次の層であり、**囮（decoy）への接触を検知し、当該端末の外向き通信を遮断する**までを自動で行います。

なお Zee の実装はこの封じ込めの層だけではありません。導入前の持ち込み物を検査する**入口ゲート（`zee gate`）**、封じ込めの**証跡の書き出し（`zee export`）**、**報告書の生成（`zee incident-report`）**も実装済みです。本書は封じ込めの層を対象とし、実装の全体は README を参照してください。

設計の原則は次の3点です。改変の方向はこの原則の範囲内としてください。

1. **侵入は発生するものとして設計する。** 脆弱性の公表から短時間で悪用が始まる事例が現実に存在し、修正の適用が間に合わない時間帯が必ず生じます。
2. **攻撃者の道具の無害化を目的としない。** 駆除・解析・反撃は行わず、封じ込めの層では**被害が外部へ流出する経路の遮断**に限定します。
3. **防御は公開によって強度が上がる。** 実装は全て可読であり、秘匿ではなく検証と指摘によって改善する方針を採ります。

## 2. 現在の実装状況（検証範囲を明示）

実機で検証した範囲と、仮想環境のみで検証した範囲を区別して記載します。

| 機能 | 状態 |
|---|---|
| 囮への接触の検知（変更系＝書き換え・削除・改名） | 動作する |
| 外向き通信の自動遮断 | 動作する。**既定は `dry_run`（観測のみ）**。`response_mode: auto` かつ `dry_run: false` を明示した場合に限り実遮断を行う |
| macOS の遮断 | 実機1台で検証済み |
| Linux の遮断（nft・iptables） | ネットワーク名前空間内で IPv4・IPv6 の遮断と復旧を実測。**物理機での検証は未了** |
| Windows の遮断 | **IPv4 は実遮断と復旧を確認**（英語版の仮想ランナー）。**IPv6 は規則の投入と再読み込み時の一致まで**で、実遮断は未検証（検証環境に IPv6 の外向き経路がないため）。**日本語版 Windows 実機での検証は未了** |
| 読み取りのみの接触 | **自動遮断の対象外**（正規のソフトウェアによる読み取りが多く、遮断は業務影響が大きいため）。検知できるかは環境により異なります：**macOS・Windows では通常の読み取りを観測できません**（OS の通知機構が読み取りを出さないため）。`ZEE_CANARY_BASE_URL` を設定した場合に限り、囮に埋め込んだ URL を攻撃者が辿った時点で、利用者が指定した外部エンドポイントで発火します（Zee 本体には戻りません）。検知できた場合の扱いは通知と手動遮断の案内に留めます |
| 外向き遮断が及ばない範囲 | ①**既に確立している通信**：macOS と Windows は接続の確立時に規則が当たるため、既存の接続は止まりません（新規の接続のみが対象。検証も新規接続で測定）。②**私用アドレス等への通信**：遮断は「外向き」を対象とするため、**RFC 1918 の私用アドレス宛ては各経路とも通します**。**IPv6 の ULA（`fc00::/7`）宛ては iptables と Windows の経路では通し、nft と pf の経路では遮断します**（リンクローカルも同様）。したがって VPN・オーバーレイ（Tailscale・ZeroTier 等）が私用アドレスで遠隔につながっている場合、その通信は止まりません。ULA でつながっている場合は経路により異なります。いずれも `cut_method: full` を選べば止まります。③**経路による差**：上記のとおり、IPv6 のリンクローカル・ULA の扱いは iptables／Windows と nft／pf で異なります。詳細は README の「外向き遮断と IPv6」および `docs/verification/real-cut.md` |
| 誤検知率 | **未測定。** 未測定の事実を「低い」と言い換えることはしない |

## 3. 現在こちらで着手している領域

作業の重複を避けるため、現在地を示します。

- Linux における遮断の実測（常設の仮想環境・nft と iptables の両経路・IPv4 と IPv6）
- 誤検知の測定（未測定の状態を数値に置き換える。まず1環境から）
- OS 別の遮断実装の改善（`netsh`・`nft`・`iptables`・`pf`。VPN・オーバーレイ下の挙動を含む）
- 文書の整備および英語版の作成

## 4. 改良が有効な領域

第2節で「未了」とした箇所が、そのまま改良の有効点です。以下は、当方の環境では充足できない項目の列挙です（依頼ではありません）。

1. **日本語版 Windows 実機での検証。** 当方は x64 の Windows 実機を保有しておらず、検証は仮想環境および英語版に限られます。実行手順は `docs/verification/real-cut.md` にあり、結果が記録されれば第2節の当該行が確定します。IPv6 の外向き経路を持つ環境での結果は、現在未測定の欄に対応します。
2. **誤検知の実例。** 正規のソフトウェアによる発報は、**欠陥の報告と同等に扱います**。単一環境では取得できない種類の情報です。
3. **攻撃側からの検証。** 隔離環境における突破の経路。防御側が想定する攻撃は、自らの設計の内側に収まる傾向があります。
4. **読み取りの検知**（macOS の Endpoint Security、Windows の Object Access 監査）。現時点で未到達の層です。資格の申請および環境面の制約により、当方では進捗が停止しています。

1 および 2 は、コードの記述を伴わない形でも成立します。
着手にあたって事前の表明は**必須ではありません**。重複を避けたい場合や相談されたい場合に、Issue で一報いただく形も**歓迎します**。

## 5. 禁止事項（改変・寄与の双方に適用）

次の各項は、**本プロジェクトにおける実装・提案・受け入れ・共同開発者としての記載の方針**です。これらに該当する改変は取り込まず、記載も行いません。

**MIT ライセンスの許諾条件を変更するものではありません。** 本書はライセンスに条件を追加しません（MIT の下でフォークして何を実装されるかは、その方の責任で判断されるものです）。以下は本プロジェクトが受け入れる範囲の表明です。

1. **ハックバック（反撃）に相当する一切の機能。** 攻撃元とみなした相手への侵入・接続の試行、妨害、停止、データの削除・改ざん、再感染を企図した送信を含みます。
2. **第三者の機器・システム・データへの無断のアクセス、取得、改変、破壊。** 攻撃者のものと推定される対象であっても同様です。**帰属の推定は誤りうる**ため、推定に基づく能動的な操作を認めません。
3. **通信の傍受、なりすまし、認証情報の窃取**、およびこれらを補助する機能。
4. **適用される法令に違反する機能。** 国・地域により、上記1〜3は犯罪を構成し得ます（日本国内では不正アクセス禁止法等に抵触し得ます）。利用者の所在地の法令に適合しない機能は受け入れません。
5. **第三者のサービスの利用規約に違反する操作**を前提とする機能。

本項は第1節の原則2（攻撃者の道具の無害化を目的としない）の具体化です。Zee の防御は、**自らの管理下にある資産の内側で完結**します。管理外への能動的な行為は、その範囲を超えます。

なお、**隔離環境における Zee 自身への攻撃検証**（第4節の3）は本項の対象外です。対象は自らが管理する検証環境に限り、第三者の資産を用いないでください。
