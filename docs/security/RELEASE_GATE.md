# 公開・配布の「実動作の関門」（zee）

出す物そのもの（公開タグ・配布物）を、実機で主要機能まで動かした記録が無いまま出さないための検査。
手元・仮想環境で通ったことは合格に数えない。

**この関門はタグの公開を止めない。** CI（`.github/workflows/release-gate.yml`）の検査はタグが GitHub に push された後に動くため、
不合格でもそのタグは公開されたまま残る（結果が赤になって知らせるだけで、タグも取り消されない）。
公開前に止めたい時は、タグを打つ前に、タグを付けるコミットで次を手元で通す（不合格なら exit 1）:
`node scripts/release-gate.mjs check --channel git-tag --artifact HEAD`

- 機械: `scripts/release-gate.mjs`
- 台帳: `docs/security/release-verification.json`（証拠は `docs/security/evidence/`）

## 1. 検証表記の3段

| 段 | 文面 | 意味 |
|---|---|---|
| 1 | 仮想環境で確認 | CI・仮想ランナー・隔離環境・手元の開発環境 |
| 2 | 実機で一部まで確認（例: 観測まで） | 実機で動かしたが、要の動作（遮断など）までは通していない |
| 3 | 実機で実動作まで確認 | 実機で要の動作を最後まで通した（zee なら `dry_run: false` の実遮断と `zee restore` の復旧まで） |

- 「検証済み」「動作確認済み」と書けるのは3段目だけ。対応OS・環境ごとに段を分けて書く。
- 3段は事実の区別であり、強みは言い切りで書く。卑下・予防線の言い回しにしない。
- 技術用語としての「署名検証済み」「検証済み取引」は対象外（環境語が同じ文に無い文は拾わない）。

現在の表記：**macOS は実機で実動作まで確認、Linux・Windows は仮想環境で確認。**
実機試験で動いたコードの版は実測していないため、版を付けた「実機で確認」は書かない（台帳の記録は `usable_for_release: false`）。

- 版（`v1.2.3`）を同じ文に書いた「検証済み」系の表記は、その版の記録で、かつ公開許可に使える記録がある環境にだけ書ける（`claims` が検査する）。

## 2. 記録の作り方（確かめた人がやる）

1. 出す版を実機で動かす（`scripts/verify-real-macos.sh` で実遮断と復旧まで）。
   版の指紋は `node scripts/release-gate.mjs id <タグ>` で出す（`docs/security/` を除く全ファイルの指紋）。
2. 実行ログ（証拠）を `docs/security/evidence/` に置き、`shasum -a 256` を取る。証拠はこのフォルダの中だけ有効。
3. `records` に1件足す:
   `{artifact, content_id, channel, env, tier:3, exercised:[実施した手順], built_by, by, at, evidence, evidence_sha256}`。
4. **作った担当と確かめた担当が同じ記録は不合格**（別の担当が確かめる）。
5. 記録を作った側が「この記録は公開許可には使えない」と判断した場合は `usable_for_release: false` と
   `unusable_reason` を書く。機械判定はこの印を見て、その記録では通さない。

## 3. 関門で止まった時

`check` は不合格時に、足りない物と次に要る手を標準エラーに出す。止めたまま黙らない。

## 4. 自己検査

`node scripts/release-gate.mjs --selftest`。通るのは「3段・別の担当・証拠一致・公開許可に使える印」だけで、
記録なし／仮想環境のみ／観測まで（2段）／別の版／別の環境／手順不足／作った人＝確かめた人／日付なし／
証拠の改変・証拠フォルダの外・シンボリックリンク／版が指紋でない、はすべて止まる。
