## 4. 報告命令の報告事項 ↔ Zee の記録

`report_export.py` の `statutory_report_items`。**Zee が出すのは材料の一部だけ**で、該当性の判断と記入は利用者が行う。推定値で埋めない。

| 報告事項（報告命令 第4条第3項） | Zee のデータ源 | 扱い |
|---|---|---|
| 一 報告の区分 | なし | 利用者が記入 |
| 二 特別社会基盤事業者の概要 | なし | 利用者が記入 |
| 三 特定侵害事象等の概要 | `incident_summary_auto`（件数・期間・未解除の遮断記録数）、`detected_at_first` / `detected_at_last` | 材料のみ。特定侵害事象等に当たるかの判断・記述は利用者 |
| 四 発生した特定重要電子計算機 | `affected_asset_ids`（利用者が `assets.toml` で付けた識別子） | 材料のみ。特定重要電子計算機に当たるかの判断は利用者 |
| 五 技術的な事項 | `events`（操作種別・検知元・確度・時刻・`decoy_ref`。`detail` は既定でマスク） | 一部のみ。通信元IP・通信内容は Zee が記録しない |
| 六 対応に関する事項 | `active_containments`（端末内の遮断記録：方式・時刻・変更したインターフェース等） | 一部のみ。それ以外の対応は利用者 |
| 七 その他特記事項 | なし | 利用者が記入 |

## 5. 任意の報告・相談の項目 ↔ Zee の記録

`report_export.py` の `report_fields`。JPCERT/CC のインシデント報告様式（https://www.jpcert.or.jp/form/ ）で一般的な項目に合わせている（**様式の最新版は今回未確認**）。

| 項目 | Zee のデータ源 | 扱い |
|---|---|---|
| お名前・組織名称・部署名・電話番号・電子メール・報告目的 | なし | 利用者が記入 |
| アクセス元IPアドレス・ホスト名 | なし（ファイル監視のみ。送信元IPを記録しない） | 不明（Zee は記録しない） |
| インシデントの内容（自由記述） | `incident_summary_auto`（事実のみ。遮断を「行った」とは書かない） | 自動生成。利用者の説明は `incident_summary_operator` に記入 |
| 発生したシステム | `affected_asset_ids`（IPアドレスではない） | Zee が提供 |
| プロトコル又はポート | なし | 不明（Zee は記録しない） |
| 関連ソフトウェア・ハードウェア | なし | 利用者が記入 |
| 発生時刻・タイムゾーン | `detected_at`（UTC の ISO8601） | Zee が提供 |
| ログ情報 | `events`（各行のハッシュは含まない） | Zee が提供。元ログのハッシュチェーンは Zee 側で検証済み（`chain_verification`） |

## 6. 改ざん検知の設計と限界

- **ハッシュチェーン**：`events.jsonl` / `metrics.jsonl` の各レコードに `prev_hash`（直前レコードの `record_hash`。ログ全体の最初は `GENESIS_HASH`）と `record_hash`（`sha256(prev_hash + 正規化JSON)`）を付ける（`telemetry/events_log.py`）。末尾の読み取り・ローテーション・追記は1つの排他区間で行い（スレッドロック＋ファイルロック）、末尾は最後の 64KiB だけを読む。
- **ローテーション**：10MB を超えると `events.jsonl.YYYYMMDD_HHMMSS` に改名。検証とエクスポートは改名済みのファイルを時系列に連結して読む。
- **検知できること**：途中の行の書き換え（`corrupted`）、途中の行の削除・並べ替え（`chain_break`）、先頭や古いローテーションファイルの欠落（`head_missing`）、ハッシュ付きの行の後のハッシュなしの行（`legacy_after_chain`）。ハッシュ導入前の行は `legacy`（未検証）として区別する。最終行が書き込み途中の可能性がある場合は `partial` として区別し、改ざん判定に含めない。ログが読めない場合は `unverifiable`（CLI は終了コード 1）。
- **検知できないこと**：末尾の行の削除（切り詰め）。ログを書き換えられる攻撃者による全ハッシュの再計算（ハッシュに鍵を使っていないため。Zee の脅威モデルは攻撃者がホスト上にいる前提＝ARCHITECTURE.md）。
- **`export_sha256`**：エクスポート自身のハッシュ。別の場所に控えた値と照合すれば「出力時点以降に変わっていない」ことは示せるが、出力前のログの正しさは示さない。
- **署名（採否）**：不採用。リポジトリには非対称鍵の基盤がなく、`recovery/auth.py` は標準ライブラリのみの方針。署名用の依存追加は方針と矛盾する。鍵をホスト上に置く限り、ホスト上の攻撃者に対する効果も限られる。
- **マスク**：`--no-redact` を付けない限り `detail`（パスを含みうる自由記述）をマスクする。`asset_id` はマスクしない（封じ込め範囲の特定に必要）。**`asset_id` に個人名・顧客名を含めないこと**（README にも記載）。`decoy_ref` は絶対パスを含まない形式（`asset_id#index`）。
