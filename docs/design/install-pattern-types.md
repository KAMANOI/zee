# 導入方式の3型（設計）

日付: 2026-11-01 ／ 状態: 設計（仮コード PA1〜PC3 は未実装）。特定の製品名・作者名は載せない。仮記号は未採番で、実装時に空いている G 番号を振る。
過剰主張をしない: LOW は「安全」ではない。「検出事項の重みの合計が判定のしきい値に届かなかった」という意味で、軽い検出事項が残っていても LOW になりうる。合格として扱うには、検査が最後まで済んだこと（検査が不完全でないこと）も別に確かめる。この3型の検査は静的で、対象を実行しない。有効性は保証しない。

## 3型の定義と判定基準

判定の写像は既存のとおり（合格 = LOW、要人手確認 = MEDIUM、不合格 = HIGH。HIGH は1つで HIGH、MEDIUM は3つで HIGH）。各表は上の行ほど条件が軽い。**不合格の条件を先に当て、どれにも当たらない時に要人手確認、それにも当たらない時に初めて合格**とする（合格の行は「要人手確認・不合格の条件がどれも無い」ことを含む）。**判定の対象は「導入方式」であり、作者や製品の善悪ではない。** 本書の「人が降格する」「人が確かめる」は、Zee の機械判定とは別に、導入する人が誤検知かどうかを見て導入の可否を決めることを指す（Zee に判定を書き換える機能があるという意味ではない）。この3型の検査は対象を実行しない（`--behavioral` を指定した時の隔離環境での実行は別の段で、本書の対象外）。Zee は無害化しない。印と記録を出し、導入するかは人が決める。

### 型(a) Web 上のスクリプトをそのまま実行する導入方式

見る物: README・導入手順・同梱スクリプトの (1) 取得内容をインタプリタへ直接渡す形、(2) 取得した実行ファイルを実行する前の検証、(3) 検証が失敗または材料なしの時の挙動、(4) 版固定。

| 状態 | 判定 | 仮コード |
|---|---|---|
| 渡す形が無く、取得物を実行前に検証し（失敗で停止）、版が固定されている | 合格 | — |
| 渡す形（`irm\|iex` 等）が文書にあり、同じ木の中のスクリプトが取得物を**失敗で止まる形**で検証している | 要人手確認 | PA1 MEDIUM |
| 検証はあるが**材料が無い時は続行**する、または版が「最新」固定なし | 要人手確認 | PA3 MEDIUM |
| 渡す形があり検証が無い、または取得して**検証なしで実行** | 不合格 | PA1 HIGH ／ PA2 HIGH |

- PA1（既存 G203 の PowerShell 系への拡張）: `irm|iex`、`iwr|iex`、`Invoke-Expression` と `DownloadString`/`Invoke-RestMethod` の組、`powershell -c "…iex…"`。
- PA2: 取得した実行ファイルを、実行前の検証なしに実行する手順。
- PA3: 検証はあるが、照合の値などの材料が無い時に止まらず続行する作り、または版を固定せず「最新」を取る作り。
- **「ハッシュ照合あり」で合格にはしない。** 同じ配布元が出すハッシュは転送中の破損・差し替えは見つけるが、配布元（アカウント・リリース）が乗っ取られた時は両方が差し替わる（推論。一次情報で検証していない）。パイプで渡す導入文自体は実行時に検証できない。だから合格は「パイプなし＋検証あり」に限り、パイプありは検証が良くても要人手確認で止める。
- 木にスクリプトが無く文書だけを検査した場合は、検証の有無を判断できないので PA1 は HIGH のまま（人が降格する）。
- 静的に見えない物: スクリプトが実行時に取得する別スクリプト、難読化、署名の中身の正しさ。

### 型(b) ファイル管理画面（エクスプローラー等）に常駐する拡張（現状の基準は Windows のみ）

見る物: 読み込まれる場所（Explorer のプロセス内か）、登録の範囲と権限（利用者単位か端末全体か）、信頼の追加、起動時の自動実行、更新時の差し替え方法。

| 状態 | 判定 | 仮コード |
|---|---|---|
| 常駐拡張の登録の兆候が無い | 合格 | — |
| 利用者単位（HKCU）でメニュー拡張を登録（`regsvr32`・`InprocServer32`・`ContextMenuHandlers`・sparse MSIX） | 要人手確認 | PB1 MEDIUM |
| Windows 全体の設定を書き換える手順の案内（クラシックメニュー切替など） | 要人手確認 | PB4 MEDIUM |
| 端末全体への登録（HKLM の shellex など）、または**端末の信頼ストア**（`LocalMachine\Root/TrustedPeople/TrustedPublisher`）へ証明書追加 | 不合格 | PB2 HIGH |
| 自動起動（`Run`）＋ 取得 ＋ 無人実行が同じ木にあり、取得物の検証が無い（更新による差し替え） | 不合格 | PB3 HIGH |

- PB2: 端末全体（HKLM など）への登録、または端末の信頼ストアへの証明書の追加。
- 常駐拡張は定義上エクスプローラーの中で動くので、**「何も見つからなければ合格」以外の LOW は出さない**。登録の兆候があれば最低でも要人手確認。
- 更新時の差し替えは (i) 動作中の DLL を `taskkill explorer` と `regsvr32` で入れ替える、(ii) 差し替える物を取得する、の2点を見る。(i) だけなら MEDIUM（PB1 の説明に含める）。PB3 は表の条件（自動起動・取得・無人実行が同じ木にあり、取得物の検証が無い）がすべてそろった時だけ出す。(ii) に検証が無くても自動起動か無人実行が無ければ PB1 の MEDIUM に留める。
- PB4 の GUID `{86ca1aa0-…}` は Microsoft が定義する既知の切替キーとして扱ってよいと見ているが、**Microsoft 公式文書は未取得**（推定）。確認できるまで MEDIUM のまま。
- 静的に見えない物: DLL の中身（バイナリは検査対象外）、署名の正当性、実行時に増える登録。

### 型(c) 初回利用時に外から実行環境とモデルを取得する型

見る物: 取得元、版・ハッシュ・リビジョンの固定、通信の安全（TLS）、保存先、認証情報の参照、取得物がコードを実行するか（`trust_remote_code`・pickle 系は G221〜G229 の担当）。

| 状態 | 判定 | 仮コード |
|---|---|---|
| 実行時の取得が無い、または版＋ハッシュ（またはコミット）固定で取得し、認証情報の参照が無い | 合格 | — |
| 版固定なしの `pip/npm install`、またはリビジョン固定なしのモデル取得（保存先が利用者の領域であることは単独では検出せず、当たった時の説明に添える） | 要人手確認 | PC1 MEDIUM |
| `http://`（TLS なし）での取得、`--trusted-host`、公式以外の `--extra-index-url`、認証情報の環境変数やトークンファイルの参照、`git+…@ブランチ名`（コミット固定でない） | 不合格 | PC2 HIGH ／ PC3 HIGH |

- PC1: 版・リビジョンを固定しない実行時の取得。PC2: 取得経路の安全を外す指定（`http://`・`--trusted-host`・公式以外の `--extra-index-url`）と、コミットでなくブランチ名を指す `git+…@ブランチ名`。PC3: 取得手順の近くでの認証情報の参照。
- 同じ「固定なし」でも、`git+…@ブランチ名` は PC2（不合格）に置き、版固定なしの登録簿からの導入は PC1（要人手確認）に置く。ブランチは取得のたびに中身が変わりうるうえ、登録簿の版番号のような記録も残らないため（推論。一次情報で検証していない）。
- 認証情報の参照は G601（秘密の置き場）と重ねて数えず、**取得手順の近く**にある時だけ PC3 を出す（近さの扱いは G214 と同じ作り方）。
- モデルの中身（pickle・`auto_map`）は G221〜G229 に任せ、ここは**取得の仕方**だけを見る。
- 静的に見えない物: ライブラリが内部で取る取得先（モデル名や大きさだけを渡すと、取得先をライブラリ側の既定で決める作りなど）、取得先の改ざん。

## 利用者向け「入れる前に自分で確かめること」

**Web 上のスクリプトをそのまま実行する導入方式（`irm … | iex`、`curl … | sh`）**
1. 実行する前に、そのアドレスの中身をブラウザで開いて読む（読めない・長すぎるなら、実行しない）。
2. 公式の配布ページから、普通のダウンロードで入れられないか探す。
3. 取得した実行ファイルの照合が書いてあるか見る。照合の値が無い時に「警告だけで続ける」作りだと、止まらない。
4. 「最新版」ではなく版を指定できるか見る。照合の値が同じ配布元から来る場合、配布元ごと乗っ取られた時は守りにならないことがある。

**右クリックメニュー・エクスプローラーに常駐する拡張**
1. 登録が「自分のユーザーだけ」か「パソコン全体」か確かめる。全体や、証明書の信頼追加（管理者の許可を求める画面）が出たら、理由が説明されているものだけ進める。
2. 自動更新が既定でオンか、更新の入手先を確かめられるか見る。オンなら、更新が検証されるかを製品の説明で探す。
3. 不具合時の戻し方（アンインストール手順）が書いてあるか見る。エクスプローラーが再起動することがあるので、作業中のファイルは先に保存する。
4. 「Windows 全体の設定を書き換える手順」は、他のアプリにも効く。戻す手順もセットで控える。

**初回利用時に環境やモデルを自動で取ってくる製品**
1. どこから何を取るか（取得元・大きさ）が説明されているか見る。大きいもの（数百MB〜数GB）は、通信量と保存先の空きを先に確認する。
2. 版が固定されているか見る。固定されていないと、取得のたびに中身が変わりうる。
3. 暗号化されていない通信（`http://`）や、公式でない配布元を使っていないか見る。
4. ログイン情報やアクセス用の鍵を求められたら、理由が分かるまで渡さない。

どの項目も、これは確認の足がかりであり、安全の保証ではない。
