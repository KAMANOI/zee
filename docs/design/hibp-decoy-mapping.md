# 置き場ごとの囮メールアドレスと、外部の漏洩索引（HIBP）による流出元の絞り込み — 設計書

> 確認日 2026-10-18。「確認済み」は一次資料（出典つき）、「推測」「未確認」は明示する。
> 過剰主張をしない方針をここにも適用する：この仕組みは**外側の補助網**であり、検知も流出元の特定も保証しない。

## 0. 目的と位置づけ

保存先（置き場）ごとに一意の囮メールアドレスを混ぜ、そのドメインが第三者の漏洩索引に収録された時、
どのアドレスが含まれていたかで**流出した置き場**を絞り込む。既存の囮（ファイル侵入検知）・
ダミー混入（価値毀損）・照会型カナリア（処理された事実の記録）を置き換えず、外側に足す一層。

索引に載るのは索引運営者が入手・取り込んだ漏洩だけ。流出から収録までの遅れ、収録されない流出がある
前提で使う（この特性は設計上の前提として本書で1回だけ書く）。

## 2. HIBP 側の事実（確認済み＝公式ページ 2026-10-18 取得）

- 無料（/Subscription）：ブラウザ検索・メール通知・Pwned Passwords・漏洩監視 API。ドメインは「Monitor domains with up to 10 breached addresses」（/Subscription）。
- 有料 Core 1：月 $4.39（年払い $52.68）、1 ドメイン、流出アドレス 25 件まで。Core 2：月 $21.59、3 ドメイン、100 件まで。「Domain counts only include domains with more than 10 breached addresses」（同）。
- ドメイン検索 API `GET /breachedDomain/{domain}` は API キー必須（**無料プランでこの API を使えるかは未確認**＝独立チェックは有料プラン対象の表示を指摘。無料で確実なのは画面での確認と通知メールのみとして設計する）。応答は `{alias: [漏洩名...]}`（@ より前だけ）。未検証ドメインは HTTP 403。ドメインは DNS または メールで管理を証明してから追加（/API/v3）。
- 公式 FAQ は「domain search requires verifying … authorised to access assets on the domain」と書くのみ。**DNS の TXT 値の形式、確認メールの宛先、サブドメインの扱い、新規漏洩時の通知の仕様は取得できず未確認**（/DomainSearch はサインイン画面）。手順書では代表が画面で見た値をそのまま使う。
- 規約・商標（HIBP の名称を製品名・出品物に使えるか）は**未確認**。Zee の文言では「索引の一例」と書き、提携・公認を示さない。

## 3. 囮アドレスの作り方

1. **専用ドメインを使う（推奨）。** 理由は3つ。(a) 実在の利用者の住所と同じドメインだと、正規の漏洩（過去の流出に載った社内アドレス等）が同じ「10 件以下」の枠を食う（対応表があれば alias で区別はできるが、枠は消費する）。(b) 既存ガードが `hdr` 等の語を含むドメインを拒否する（`_DOMAIN_ORIGIN_WORDS`）ので `hdr-ai.com` はそのままでは使えない。(c) ドメインが HDR を名乗ると、盗んだ側が囮と気づく手がかりになる。ドメイン名は無関係に見えるものを使う。
2. **置き場 1 つにつきアドレス 1 つ**（`issue_place_email`）。ローカル部は既存の安全トークン（32桁16進）で、置き場名・日付を含まない。**未評価の点**：32桁16進＋少数だけの専用ドメインは、投入先の通常の顧客メール群から形式で浮く可能性がある（検出されるという断定ではなく、確かめていない回避経路）。実投入前に、投入先データの形式・頻度との整合を比べる検証を行う（判断カードの条件）。同じ置き場へ再実行しても同じアドレスを返す。ドメインは対応表に一緒に保存し、別ドメインでの再発行は拒否、照合でもドメインを指定させる。発行は鍵ファイルで直列化し（並行実行でも上限・一意が崩れない：試験済み）、対応表が壊れている／権限が緩い場合は黙って続けず停止する。
3. **件数の上限 10。** 1 置き場 1 アドレスなので、**この対応表から発行した**囮は最大 10 件。ただし別の対応表から同じドメインへ発行した場合、台帳を失って再発行した場合、過去に別人が使ったドメインを取得した場合は数えられない（§6 は条件付きの初期見積もり）。
4. **ダミー混入のメール列とは別ドメインにする。** ダミー混入は 1 回の生成で多数のアドレスを作るため、同じ監視ドメインに載せると 1 回の流出で 10 件を超える。監視対象のドメインには置き場用の少数だけを置き、ダミー混入側は別ドメイン（監視しない、または有料枠で監視）にする。
5. **対応表** ＝ レジストリの jsonl（所有者のみ読み書き 0600）。`purpose` に `place:<置き場名>`、`decoy_path` にトークン。置き場とは別の場所（別ディスク／別アカウント）に置く。レポート・ログには**件数と命名規則（32桁16進＋`@専用ドメイン`）まで**を書き、実アドレスは対応表にだけ置く。
6. **受信（任意）**：索引への収録を見るだけなら受信箱は要らない。迷惑メール到着を兆候として記録したい場合だけ、専用ドメインのキャッチオールを 1 つの受信箱へ転送する（既存のメール転送サービスで足りるか・無料枠は**未確認**）。Zee は SMTP 受け口を作らない（2026-10-13 代表決定）。受信は**記録のみ**で、返信・開封・リンク踏みは行わない（カナリア無干渉ルール）。

## 5. 流出元の絞り込み手順（運用）

1. 索引から通知（またはダッシュボードの確認）が届く／または API で `GET /breachedDomain/{専用ドメイン}` を取得（API キーは有料枠か無料枠かの範囲は未確認）。
2. 結果 `{alias: [漏洩名]}` を `locate(registry, 専用ドメイン, 結果)` に渡す（Zee は索引へ通信しない）。
3. 出力は「関連する投入先の候補」と「対応表に無い alias」。後者は**捨てずに報告**（別経路で漏れたアドレス、または表の欠落）。
4. 当たりは「その囮を含むデータが漏れた」ことしか示さない。A のダンプを B へバックアップすれば A の囮も B にあり、B だけからの流出でも A が当たる。対応表自体の流出でも同様。したがって**複製先・配置日・廃止の履歴を置き場ごとに残し**、候補の各置き場について鍵・権限・アクセス記録を確認してから経路を判断する（対応は代表判断）。API の結果は累積なので、複数の当たりを「同時に流出した」と読まず、前回結果との差分で見る。HIBP 自身も出所が確定しない・加工された漏洩を含むと説明している（FAQ、独立チェックの指摘）。
5. 限界（推測を含む）：漏洩データに**混ぜた囮が含まれない場合**（別の置き場だけの流出）は何も出ない。索引に収録されなければ出ない。受信した迷惑メールは「その宛先が使われた」兆候であり、転売の事実までは示さない（直接送信・探索・テスト送信もありうる）。宛先は置き場ごとに一意なので候補の置き場の手がかりにはなる。

## 6. 無料枠（流出アドレス 10 件以下）の見積もり

- **条件付きの初期見積もり**：専用ドメインに置く囮は置き場の数だけ（初期案 4〜6）。この対応表から発行する限り最大 10 件で、無料枠に収まる見込み。運用の条件：ドメイン単位で発行履歴を 1 つの対応表に統合する／導入前に索引で当該ドメインの収録数を確認する／件数増加を月次で見る／超過したら判断カードで上げる。
- 正規利用者のアドレスを専用ドメインに置かないので、収録される非囮アドレスは 0 の見込み（推測：他人が偶然このドメインのアドレスを使うことは無い）。
- 超える場合は、(a) 上限を超えて置き場を増やす (b) ダミー混入のメール列を同じドメインで監視する、のどちらか。**今回は (a)(b) とも提案しない**＝有料プランの提案は不要（Core 1 は 25 件までで、(b) の想定件数には届かないため効果が薄い）。有料提案規程の 5 項目は「対象外（無料で足りる）」と記録する。
- 費用が出るのは**専用ドメインの新規取得**だけ（年額は**情報なし**＝購入前に登録業者の画面で要確認）。判断カードで 5 項目つきで上げる。

## 7. Zee へ組み込むか、HDR 社内運用に留めるか（推奨）

**推奨：生成・対応表・オフライン照合（`place_email.py`）だけを Zee（MIT・無料・標準ライブラリのみ）に入れる。索引への通信・API キーの取り扱い・ドメイン監視の設定は Zee に入れず、利用者／HDR の手作業（手順書）にする。**
理由：(1) 外部の有料プランを前提にしない（Zee の方針）。(2) 索引の API キーを Zee が持つと秘密の置き場が増える。(3) 索引の仕様（通知方式・サブドメイン）が未確認で、固定すると壊れる。
HDR 社内での使用は同じ部品を使う。公開時の注意：README に書くのは仕組みと限界までで、「流出を検知する」「特定できる」と断定しない。

## 目的判定

- 問1：Zee の関門（実運用の計測）を直接は進めない。「盗まれた後に気づく」外側の網を足し、流出元の絞り込みという未整備の工程を前に進める。
- 問2：「無害化しない」「過剰主張しない」「MIT・無料」「実在の人と重ならない」を守る。囮は自分が管理する専用ドメインのみ＝実在の人のアドレスと重ならない。減らす操作なし。
- 問3：資産を残す案＝既存部品（`issue_query_canary`・レジストリ）を再利用した。新設は 1 ファイルのみ。
