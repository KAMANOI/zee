## How to read this

- **Table 1 (implemented)** lists only features that are on `main` and are called from a `zee` command (`gate` / `watch` / `export` / `incident-report`). **Table 2 (designed / not implemented)** is a separate table and is never mixed with Table 1.
- The **OWASP column** gives the OWASP 2025 item the feature addresses. The **ATT&CK column** gives the technique whose execution produces the behaviour the feature inspects or observes. What Zee identifies is the kind of contact with a decoy (read or change) or a pattern inside an artifact — not the technique itself (for example, encryption versus destruction). Technique IDs are an index for naming that behaviour in a common vocabulary.
- **Code evidence** is written as `file:function`. The **source statement** column summarises, with short quotations, the matching passage of each primary source.
- Of the contacts with a decoy, **only change-class contacts (write, delete, rename) trigger automatic containment**. **A read is notified only, and a person decides whether to cut** (`zee cut`). Automatic cut runs only for an asset whose profile sets `response_mode: auto` explicitly and `dry_run: false`.
- Zee does not connect to or act on an attacker's machine. The exit-side features stop at detection, notification, cutting the local host and writing out evidence; connecting that evidence to the police, the PPC or another contact point is done by a person ([containment-report-mapping.md](./containment-report-mapping.md)).
- Effectiveness has not been measured (see Project Status at the top of the README). This table shows which shared vocabulary can describe which feature; it is not a detection rate or a protection rate.

## Table 1 — Implemented features

### A. Entry gate (`zee gate`) — OWASP A03

OWASP [A03:2025 Software Supply Chain Failures](https://top10.owasp.org/2025/A03_2025-Software_Supply_Chain_Failures/) lists, as vulnerabilities, using “components from untrusted sources … in or can impact on production environments” and not having “a change management process or tracking of changes within your supply chain”. The entry gate inspects AI skills, MCP servers, npm and PyPI packages and VS Code extensions **before** they are adopted, without running them.

### B. Exit side (decoys, detection, notification, containment, evidence) — OWASP A09

OWASP [A09:2025 Security Logging and Alerting Failures](https://top10.owasp.org/2025/A09_2025-Security_Logging_and_Alerting_Failures/) names, among its preventive controls, “Add ‘honeytokens’ as traps for attackers … any access generates logging data that can be alerted with nearly no false positives” and “Ensure all transactions have an audit trail with integrity controls to prevent tampering or deletion”. Zee's exit side corresponds directly to these two.

Usage notes:

- The range of decoy contacts Zee can observe depends on the OS. Linux observes read, open and change directly. macOS and Windows observe change directly; a read is seen only when the canary URL of R6 is followed (with `ZEE_CANARY_BASE_URL` set) ([detection capability matrix in the README](../README.en.md)). Windows has not been verified on real hardware.
- The hash in R9 is unkeyed. It does not detect an on-host attacker who recomputes the whole chain, nor truncation of the end of the log. Keep a copy somewhere separate ([threat-model.md](./threat-model.md#evidence-store-and-containment-export)).
- R2–R4 look at change-class contact with a decoy. They act when ransomware, a wiper or similar touches a decoy; an attack that never touches a decoy is outside their scope.

## Maintenance rules

- When the code location (`file:function`) changes, change this table in the same commit. If they disagree, one of them is stale.
- When OWASP or ATT&CK publishes a new version, re-check that each item and technique ID still exists and that its definition still matches, and update "Versions and date checked". If a technique ID is merged or retired, replace it with the new ID rather than keeping the old one.
- A row goes into Table 1 only when (1) the code is on `main`, (2) a `zee` command actually calls it, and (3) the matching OWASP / ATT&CK passage was checked in the primary source.
